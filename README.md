# 空き日程マッチ (avail-match)

Google カレンダーの「予約スケジュール」ページ(`calendar.google.com/calendar/appointments/...`)のリンクを **2つ以上** 入力すると、それぞれの空き時間を読み取り、**全員に共通する空き時間** を計算して、先方に送れる共有リンクを発行する Web アプリです。

- 2人分の予約ページを貼り付ける → 共通の空き枠を一覧表示
- 「共有リンクを作成」で、結果だけを表示する読み取り専用ページ (`/share?d=...`) の URL を発行(先方はインストール不要でブラウザで開くだけ)
- インストールが要らない Web アプリ形式なので、Chrome 拡張機能に比べて管理・共有がシンプル

## 重要な制約(必ず読んでください)

Google はカレンダー予約ページの空き時間を取得できる公式 API を提供していません。このアプリは Playwright で予約ページを実際にレンダリングし、DOM から空き時間を読み取っています。そのため **Google 側の画面変更で突然動かなくなる可能性があります。**

実際のページ(利用者に DOM を確認してもらった結果)は、小さいカレンダーで日付をクリックして枠を切り替える形式ではなく、**日付ごとのセクションが縦に並んだリスト形式** で、下にスクロールするとさらに先の日付が読み込まれます。各時刻枠のボタンは `data-date-time` 属性にその枠の開始時刻を **UTC ミリ秒の Unix タイムスタンプ** で持っています(例: `data-date-time="1789686000000"`, `aria-label="08:00"` は `2026-09-18T08:00` JST)。これはテキストやページ上のタイムゾーン表示を解析するより確実なので、`lib/scrape.ts` はテキスト解析ではなくこの属性を直接読み、日付が変わっても対応できるよう `scrollForMore` でページを下までスクロールしながら集めています。

この前提(リスト形式・`data-date-time` 属性・スクロールで先の日付が読み込まれる)が崩れた場合は、`SCRAPE_DEBUG=1 npm run dev` で起動し、失敗時に保存される `/tmp/avail-match-debug-*.png` / `.html` を見ながら `lib/scrape.ts` の `collectSlotEpochs` / `scrollForMore` を実際の DOM 構造に合わせて調整してください。

## セットアップ

```bash
npm install
npm run dev
```

`http://localhost:3000` を開いて、予約ページの URL を2つ以上入力してください。

## デプロイ

Playwright はヘッドレス Chromium を起動して動くため、**Vercel の Edge Functions のような制約の強いサーバーレス環境より、常駐 Node サーバーとして動かせるホスティング(Render / Railway / Fly.io / 自前の VPS など)の方が安定します。**

同梱の `Dockerfile` は Playwright 公式イメージ(Chromium 同梱)をベースにしているので、そのまま Render や Fly.io、あるいは任意の Docker 対応ホストにデプロイできます。

```bash
docker build -t avail-match .
docker run -p 3000:3000 avail-match
```

Render / Railway を使う場合は、リポジトリを接続して「Dockerfile を使う」設定にするだけで自動デプロイできます(git push するたびに再デプロイされるので運用が楽です)。

## 仕組み

1. `POST /api/scrape` に入力された予約ページ URL 一覧を渡す
2. `lib/scrape.ts` が Playwright で各ページを開き、指定日数分の空き枠を読み取る
3. `lib/intersect.ts` が各カレンダーの空き枠を区間としてマージし、全カレンダーに共通する区間だけを計算する
4. 結果はその場で表示されるほか、「共有リンクを作成」を押すと計算結果を URL に埋め込んだ `/share` ページのリンクが発行される(サーバー側に保存しないので、リンクを知っている人は誰でも読み取り専用で閲覧できる)
